# Icon Platform M+ SD for Cubase – v4.1.0-rc1 (release candidate)

This is a **release candidate**. Please try it in a non-critical project first
and report any problems on the
[issue tracker](https://github.com/woodcockr/cubase-bfw-platformplussd/issues).

Highlights:

- **Jog wheel modes**: Nudge, Scrub and Shuttle.
- **MIDI CC page configuration file**: set your own CCs and names with a text editor.
- **Quieter script console**: only startup status, warnings and errors are shown.

---

## Download and install

| Download | Use it when |
|---|---|
| `bfw-platformmplussd-v4.1.0-rc1.zip` | **New install, or you have never edited `midi-cc-config.js`.** Contains the full folder layout. |
| `bfw_platformmplussd.js` | Updating the driver only, keeping your existing `midi-cc-config.js`. |
| `midi-cc-config.js` | A fresh copy of the default MIDI CC configuration. |

1. Close Cubase.
2. Extract the zip into your Cubase *Local* driver scripts folder:

   - **Windows:** `Documents\Steinberg\Cubase\MIDI Remote\Driver Scripts\Local\`
   - **macOS:** `~/Documents/Steinberg/Cubase/MIDI Remote/Driver Scripts/Local/`

   (If your Documents folder is synced by OneDrive, it is under `OneDrive\Documents\…`.)

   You should end up with:

   ```
   Local/
     bfw/
       platformmplussd/
         bfw_platformmplussd.js
         midi-cc-config.js
   ```
3. Start Cubase.

> **Upgrading from v4.0.x?** `midi-cc-config.js` is new in this release, so
> **use the zip** (or download both files). Without it, the MIDI CC page still
> works with the built-in defaults, but the script console shows a
> "could not load the file" error.
>
> **Upgrading later?** Extracting the zip **replaces** `midi-cc-config.js`. If
> you have edited it, back it up first and copy it back afterwards, or download
> only `bfw_platformmplussd.js`.
>
> If an update does not seem to take effect, see *Known Issues* in the
> [README](https://github.com/woodcockr/cubase-bfw-platformplussd#known-issues)
> about the cached MIDI Remote settings file.

## New: Jog wheel modes (Nudge, Scrub, Shuttle)

Make sure both hardware **Zoom** lights are **off**, so that the wheel acts as a jog wheel.
**Tap the wheel** to cycle through three modes. The current mode letter is shown
at the right-hand end of the top LCD row:

**Nudge (`N`) → Scrub (`S`) → Shuttle (`H`) → Nudge …**

Cubase always starts in Nudge.

| Mode | What the wheel does |
|---|---|
| **Nudge (`N`)** | Steps the project cursor left/right with Cubase's *Nudge Cursor* commands (the previous behaviour). |
| **Scrub (`S`)** | Scrubs audio at the cursor as you turn, like dragging the cursor by hand. Scrubbing stops about 0.2 s after you stop turning. Requires Cubase 15. |
| **Shuttle (`H`)** | A speed selector for playback. It starts at **Stop**. Each click clockwise steps up through forward speeds (1/8x, 1/4x, 1/2x, 1x, 2x, 4x, 8x). Each click anticlockwise steps back towards Stop and then into the same reverse speeds. The speed stays latched when you let go; turn back to Stop, or tap to leave Shuttle, to stop. |

Notes:

- Leaving Shuttle, changing mode, pressing a hardware transport button or
  switching Zoom on all release the Shuttle speed and reset it to Stop.
- While Cubase is recording, the wheel will not start Scrub or Shuttle movement.
- At startup the script console reports `Direct Access Scrub ready …` and
  `Direct Access Shuttle ready …`. If you see a `Warning: Direct Access … disabled`
  message instead, that mode is unavailable in your Cubase version.

### Known issue: Scrub skips back after a lot of continuous jogging

When you scrub continuously for a long time, the cursor can occasionally **jump
back** a short distance. This comes from how Cubase handles the scrub position
and also happens with other scripts that use the same method.

**Workaround:** pause briefly every few turns, lifting your hand off the wheel
for a moment, rather than spinning continuously. Short bursts of scrubbing
rarely skip. Use Shuttle for moving long distances.

## New: MIDI CC page configuration file

The MIDI CC page (Stream Deck *MIDI CC* button) turns the eight faders into MIDI
CC controllers. You can now choose which CC each fader sends, and the name shown
on the LCD, by editing a plain text file. No programming is needed.

### Default assignments

| Fader | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| CC | 1 | 11 | 2 | 21 | 7 | 16 | 17 | 18 |
| Name | Dynamics | Expression | Breath | Vibrato | Volume | General Purpose 1 | General Purpose 2 | General Purpose 3 |

These names follow orchestral sample library conventions. Long names are
abbreviated to fit the 6-character LCD.

### Where the file is

`midi-cc-config.js`, in the same folder as the driver:

```
…\MIDI Remote\Driver Scripts\Local\bfw\platformmplussd\midi-cc-config.js
```

### How to edit it

Open it in any text editor (Notepad, TextEdit, VS Code). **Change only the lines
between `BEGIN MIDI CC CONFIG` and `END MIDI CC CONFIG`:**

```js
module.exports = { rows: [
  // BEGIN MIDI CC CONFIG
  "1, Dynamics",
  "11, Expression",
  "2, Breath",
  "21, Vibrato",
  "7, Volume",
  "16,",
  "17,",
  "18,",
  // END MIDI CC CONFIG
]};
```

Rules:

- Each line is one fader, in order: the first line is fader 1, and so on.
- Format: `"<CC number>, <name>",`, with **double quotes** and a **comma at the
  end of the line**.
- **CC number** must be a whole number from **0 to 127**.
- **Name** is optional. Leave it empty (for example `"16,",`) to use the standard
  MIDI name. Use plain letters, digits and punctuation, and **no commas**.
- Up to **8** lines. If there are fewer, the remaining faders use the defaults.
- Lines whose text starts with `#` are ignored. Use this to keep alternatives,
  for example `"# 64, Sustain",`.

Example: put Volume on fader 1 and a custom Legato control (CC68) on fader 2:

```js
  "7, Volume",
  "68, Legato",
```

After saving, **reload the script** (the *Reload Scripts* button in the script
console, see below) or restart Cubase.

On the controller, you can still turn a channel's encoder to choose a different
CC temporarily. Turning the encoder never sends a CC. Moving the fader sends it.
Temporary choices reset when the script reloads.

### How to tell if the file has a mistake

A mistake in the file **will not stop Cubase or the controller from loading**.
Instead, the MIDI CC page uses the complete built-in defaults and writes a
message to the **MIDI Remote Script Console**.

To open the console in Cubase, right-click the **MIDI Remote** info line,
activate **Scripting Tools**, then click **Open MIDI Remote Script Console**.

- **File OK:**

  ```
  [MIDI CC config] midi-cc-config.js: loaded CC1 Dynamics, CC11 Expression, …
  ```

- **File has errors:** one line for each problem, giving the row and the reason,
  then a fallback message:

  ```
  [MIDI CC config] midi-cc-config.js: ERROR row 7 "200,": CC number must be a whole number from 0 to 127
  [MIDI CC config] midi-cc-config.js: Using built-in MIDI CC defaults.
  ```

- **File missing or not readable** (for example, a quote or bracket was
  deleted):

  ```
  [MIDI CC config] midi-cc-config.js: ERROR could not load the file: …
  [MIDI CC config] midi-cc-config.js: Using built-in MIDI CC defaults.
  ```

  Restore the lines outside the BEGIN/END markers, or replace the file with a
  fresh copy from this release.

A quick sign of a problem without opening the console: if the fader names on the
MIDI CC page show the defaults (Dynmcs, Exprss, …) instead of your names, check
the console.

## Other changes

- **Quieter script console.** Development messages, such as binding creation and
  LCD updates, are no longer printed. You will see only startup status, warnings
  and errors.
- **Fixed** 17 misleading binding warnings at startup (`Master button … not found`
  and `Could not resolve host value … "customVariable"`). These came from unused
  leftover configuration. All Stream Deck page buttons work as before.
- The *Idle callbacks are not supported* warning (older Cubase versions only) now
  prints once instead of repeatedly.

See [CHANGELOG.md](https://github.com/woodcockr/cubase-bfw-platformplussd/blob/main/CHANGELOG.md)
for the full list.
